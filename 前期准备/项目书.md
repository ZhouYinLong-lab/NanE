# NanE 南易校园互助平台

**EL智能应用开发与创新大赛 · 交互组**

---

## 一、项目背景

### 1.1 痛点来源

大学宿舍里有一类特殊的浪费——"一次性凑数购买"。碘伏、棉签、退烧贴、创可贴……这些物品往往因为一次突发需求被大量买入，用完寥寥几个后便长期闲置，最终在保质期内悄悄过期丢弃。

与此同时，另一个宿舍里的同学正在深夜因发烧找不到退烧药而焦虑。

这两种场景同时存在，却彼此不知。

### 1.2 现有方案的不足

- **宿舍群/朋友圈求助**：信息扩散范围有限，响应慢，难以持续沉淀
- **二手平台（闲鱼等）**：面向大众，非校园场景，药品类发布受限，陌生人信任成本高
- **校园表白墙/论坛**：非结构化，无法检索，一次性信息

目前南大没有专门面向校内耗材共享、以"同楼栋优先"为核心逻辑的轻量平台。

---

## 二、项目简介

**项目名称**：NanE 南易校园互助平台

**一句话描述**：一个让南大同学把低风险应急耗材和非处方常见药品笼统分类信息免费共享给有需要同学的校园互助平台，优先匹配同楼栋、同宿舍群和同校区。

**核心定位**：
- 物品范围：以应急耗材（创可贴、碘伏棉签、防护用品等）和非处方常见药品笼统分类（感冒药、退烧药、过敏药等）为核心，不涉及金钱交易
- 服务对象：南京大学在校学生（初期聚焦2025级本科生）
- 核心价值：减少浪费、应急互助、校园信任网络

## 三、功能设计

### 3.1 发布物品

**准入规则**
- 物品类型分为**耗材**和**药品**
- 耗材不要求用户选择细分类，平台统一按“应急耗材”处理
- 药品仅允许笼统非处方分类，如“感冒药/退烧药/过敏药/肠胃药/其他非处方药”
- 严禁处方药、管控药、拆封不明物品和任何形式收费交易
- 所有发布内容均需人工审核后上架

**上传要求**
- 有保质期物品：需填写保质期（或购买日期），平台按类目标准保质期自动推算下架时间，到期自动下架
- 必须说明可提供数量
- 存放位置精确至楼栋（必填），房间号（选填）

### 3.2 用户账户

**注册**
- 下一阶段接入**小助手 challenge-code 身份验证**，确保校园身份真实性
- 必填：微信号或QQ号（用于线下联系）、校区、楼栋
- 注册时绑定校区/楼栋信息，作为搜索排序依据

**隐私保护**
- 物品详情页默认不展示联系方式
- 点击"我要领取"后方可查看发布者联系方式
- 每人每日查看联系方式次数设上限，防止信息滥用

### 3.3 搜索与发现

**搜索排序逻辑**
1. 同楼栋物品优先展示
2. 其次同宿舍群
3. 再次同校区
4. 最后其他校区

**筛选功能**
- 按校区筛选
- 按楼栋筛选
- 按类型筛选（耗材/非处方药品）
- 药品按笼统分类筛选（感冒药/退烧药/过敏药等）

**首页推荐**
- 展示用户所在楼栋/校区的最新发布
- 展示即将到期（3天内）的物品，提示尽快认领

### 3.4 审核机制

- 所有发布进入待审队列，由平台管理员（初期为团队成员）人工审核
- 审核标准：是否符合免费互助边界、药品是否为非处方常见笼统分类、有效期信息是否填写、位置是否合理
- 审核通过后上线，未通过则通知发布者说明原因

### 3.5 平台声明

平台仅提供信息展示与撮合，不介入线下交接过程。所有物品均为免费共享，物品质量由发布者负责，领取者自行判断。

## 四、技术方案

> 当前已完成可演示和可部署的 MVP 工程，后续在同一套后端上扩展 Web 和 EXE。

| 层级 | 当前技术选型 |
|------|----------------|
| 小程序前端 | 微信原生小程序，WXML / WXSS / JS |
| 后端 | Node.js 原生 `http` 服务 |
| 数据库 | PostgreSQL |
| 管理后台 | 同一 Node 服务内的轻量 Web 后台 `/admin` |
| 身份认证 | 当前 Demo 登录；下一阶段接入小助手 challenge-code 身份验证 |
| 部署 | Azure VM + Nginx + Let's Encrypt HTTPS |
| 域名 | `api.zylatent.com` 提供 API，`nane.zylatent.com` 提供管理后台和后续 Web 入口 |
| 桌面端 | 后续优先使用 Tauri 封装 Web 客户端 |

**关键技术点**
- 基于用户楼栋和宿舍群规则的分层排序（不涉及GPS定位，保护隐私）
- 保质期自动下架定时任务
- 联系方式查看频次限流（当前 PostgreSQL 记录，后续可引入 Redis）
- 小助手账号体系接入后，由 NanE 后端签发自己的 JWT，三端共用登录态

## 五、用户使用场景

### 场景一：发布者视角

> 小李买了一盒20片退烧贴，只用了3片，还剩17片。她打开平台，选择分类"退烧/降温"，填写保质期2026年12月，数量17片，存放位置"鼓楼校区XX楼"，提交审核。审核通过后，同楼栋的同学可以在搜索中优先看到这条信息。

### 场景二：领取者视角

> 深夜，小王发现室友发烧，想找退烧贴。他打开平台搜索"退烧贴"，首先出现的是同楼栋小李发布的那条信息。他点击"我要领取"，查看到微信号后直接加好友沟通取货，10分钟内解决问题。

### 场景三：应急搜索

> 小张崴脚了需要绷带，他在平台按"医疗耗材"分类筛选，选择本校区，找到距离最近的发布者，顺利取到绷带。

## 六、项目创新点

1. **垂直场景切入，解决真实痛点**：专注于应急耗材和非处方常见药品笼统分类互助，相比通用闲置平台更聚焦、审核更严格，真正解决宿舍应急物品浪费问题

2. **楼栋优先的地理分层逻辑**：不依赖GPS，通过用户注册时填写的楼栋信息实现"近邻优先"排序，兼顾隐私与便利

3. **保质期生命周期管理**：自动追踪药品保质期并到期下架，保障物品安全，这是通用闲置平台所不具备的功能

4. **白名单 + 人工审核双保险**：针对药品安全性的专项设计，区别于普通二手平台

5. **接入校园身份认证**：基于小助手 challenge-code 身份体系，建立校园内可信的共享网络，降低陌生人信任门槛
