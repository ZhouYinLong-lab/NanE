# NanE 南易演示脚本

## 1. 首页发现

打开网页端 `https://nane.zylatent.com`，展示 NanE 的核心定位：校园互助信息撮合、免费共享、同楼栋和临近宿舍群优先。

演示点：

- 搜索“创可贴”或“感冒药”
- 切换“耗材”或“非处方药品”筛选
- 说明推荐排序为同楼栋 > 同宿舍群 > 同校区 > 其他校区
- 说明首页只展示审核通过的 `online` 物品

## 2. 物品详情与联系方式限制

进入任意物品详情页。

演示点：

- 位置、有效期、发布者信息
- 风险提示：免费互助、药品仅限非处方常见分类、禁止处方药/管控药、自行判断风险
- 点击“我要领取，查看联系方式”
- 说明后端会记录 `contact_views`，每日最多 5 次
- 联系并实际领取后，点击“我已联系并领取，提醒发布者确认”
- 发布者会收到邮箱提醒，并可在“我的发布”里确认领取
- 发布者确认后，系统自动扣减数量；扣到 0 时物品自动下架

## 3. 登录与账号资料

进入“我的”区域，演示南京大学学生邮箱验证码登录。

演示点：

- 登录前必须阅读并同意用户协议
- 邮箱后缀固定为 `@smail.nju.edu.cn`
- 验证码邮件由 NanE SMTP 配置发送
- 登录后需要补全昵称、校区、楼栋，宿舍号可选
- 未补全资料时不能发布或查看联系方式

## 4. 发布互助

进入发布页，填写一个低风险耗材或非处方常见药品分类。

演示点：

- 物品类型：耗材 / 药品
- 耗材无需细分类，药品使用“感冒药/退烧药/过敏药”等笼统分类
- 选择一个 Font Awesome 物品图标，说明图标仅用于辅助识别
- 微信或 QQ 至少填写一项，用于线下联系
- 有效期格式校验
- 免费互助、禁止处方药/管控药和禁止收费交易声明
- 提交后状态为 `reviewing`，审核前首页不可见

## 5. 管理后台审核

打开：

```text
https://你的 API 域名/admin
```

当前生产后台：

```text
https://nane.zylatent.com/admin
```

演示点：

- 管理员登录
- 查看待审核物品
- 通过或驳回
- 审核动作写入 `review_logs`

## 6. 数据同步

审核通过后回到网页端首页刷新。

演示点：

- 网页端、小程序端、服务器 API、管理后台共用 PostgreSQL
- 后台审核后，网页端立即读取同一份数据

## 7. 后续多端路线

简短说明：

- 当前网页端已打通邮箱登录、发布、审核、展示、联系方式、领取确认和邮箱提醒链路。
- 南哪小帮手 challenge-code 作为备用身份验证链路，后端验证后签发自己的 JWT。
- 小程序端因备案暂缓上线，代码保留；后续 Web、微信小程序和 Tauri/EXE 仍共用同一套 API 和数据库。

### 录制避坑

- 不要说"小程序已上线"，当前主入口是网页版。
- 不要说"短信提醒"，当前是邮箱提醒。
- 不要说"平台配送"，线下交接由用户自行完成。
- 不要说"提供医疗建议"，药品只做非处方常见笼统分类。
- 所有真实邮箱、验证码、联系方式、管理员密码都要打码。
