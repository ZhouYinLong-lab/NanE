# NanE Iteration 2 — 前端深化打磨与后端分页

**日期**: 2026-06-10
**分支**: dev
**范围**: 登录流程简化、发布表单结构化、空状态插画、后端分页

---

## 一、本轮改动

### A. 前端体验

| # | 改动 | 说明 |
|---|------|------|
| 1 | 空状态 SVG 替换 | 5 个插图从 64px 升级为 72px，图标设计更具辨识度（房屋、放大镜+靶心、文档+横线、X 圆、人物+加号） |
| 2 | 发布表单字段集 | 16+ 表单元素分组为 3 个 `<fieldset>`（基本信息、物品详情、联系方式与确认），每段带紫色 `<legend>` 标题 |
| 3 | 登录卡片滚动定位 | `#mineLoginCard` 添加 `scroll-margin-top: 80px`，锚点跳转时不会被顶栏遮挡 |
| 4 | fieldset/legend 样式 | 圆角边框、紫色字重 legend，浅色/深色双主题适配 |

### B. 后端完善

| # | 改动 | 说明 |
|---|------|------|
| 1 | GET /api/items 分页 | 新增 `limit`（默认 50，上限 100）和 `offset`（默认 0）查询参数 |
| 2 | 分页响应元数据 | 响应新增 `total`、`offset`、`limit`、`hasMore` 字段，前端可按需加载更多 |

### C. CSS 暗色模式补全

- `fieldset` 边框颜色适配暗色主题
- `legend` 颜色保持紫色可读性

## 四、待改进（进入 Iteration 3）

### 前端
1. **草稿保存**：发布表单填写后切换页面数据丢失
2. **联系方式加密**：数据库泄露时微信/QQ 暴露
3. **通知机制**：领取确认缺少推送/邮件通知
4. **分页前端消费**：首页"加载更多"按钮对接后端分页参数
5. **性能优化**：图标选择器可用虚拟滚动或懒加载

### 后端
1. **自动过期改为定时任务**：每次 GET 请求执行 UPDATE 的开销随数据增长而增大
2. **联系方式加密存储**：AES 加密 wechat/QQ 字段
