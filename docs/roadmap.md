# NanE 路线图

NanE 当前采用“网页端先稳定，小程序端保留并等待备案，多端共用 API”的路线。

## 当前阶段：网页版 MVP 验收

目标：让 NanE 可以被测试同学和评审完整体验。

已完成：

- 网页端首页、详情、发布、我的发布。
- 南京大学学生邮箱验证码登录。
- 用户协议确认。
- 账号资料：昵称、校区、楼栋、宿舍号。
- 管理后台审核。
- PostgreSQL 持久化。
- 联系方式每日 5 次限流。
- 领取确认、数量扣减、归零自动下架。
- 领取确认邮箱提醒。

验收重点：

- 游客只能浏览，不能查看联系方式。
- 登录用户必须补全资料才能发布或获取联系方式。
- 药品类保持非处方笼统分类。
- 管理员审核后数据实时同步。

## 小程序路线

小程序端代码保留在 `miniprogram/`。

恢复小程序上线前需要：

- 完成微信小程序备案。
- 微信后台配置 request 合法域名 `https://api.zylatent.com`。
- 补充隐私保护指引。
- 使用真实 AppID 回归首页、详情、发布、我的发布。
- 确认小程序端登录策略与网页端保持一致。

## 桌面端路线

桌面端不重新实现业务逻辑，优先封装 Web 客户端。

建议路线：

1. Web 端稳定后，用 Tauri 封装。
2. 复用 `https://api.zylatent.com/api`。
3. 保留浏览器端作为主入口，EXE 作为展示或离线入口补充。

## 风险与边界

- 平台只做免费互助信息撮合，不做交易。
- 药品类只允许非处方常见笼统分类。
- 不提供医疗诊断、用药建议或处方判断。
- 宿舍号和联系方式严格限制展示范围。
- 邮箱和南哪小帮手密钥只保存在服务器 `.env`。
