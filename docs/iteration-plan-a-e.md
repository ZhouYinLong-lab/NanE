## 迭代 A — 发布表单体验增强

**目标**: 让发布流程更安全、反馈更即时，减少提交失败后的返工。

### A1. 字段级内联校验
- 标题为空 → 输入框下方红色提示"请填写物品名称"
- 数量 ≤ 0 → 红色提示"数量至少为 1"
- 微信 + QQ 均为空 → 各自下方提示"至少填一项"
- 未勾选免责声明 → 复选框区域红色边框 + 提示
- **实现**: `submitPublish()` 前置校验从 `message.textContent` 改为字段级 DOM 插入，校验通过后清除

### A2. 实时字数统计
- 标题输入框右侧显示 `{n}/30` 字数
- 补充说明 textarea 右下角显示 `{n}/200` 字数，超限标红
- **实现**: `input` 事件监听 + CSS `::after` 伪元素定位

### A3. 提交前确认摘要（可选）
- 点击"提交审核"后弹出确认对话框，展示：物品名称、类型、数量、校区楼栋、有效期
- "确认提交" + "再检查一下" 两个按钮
- 仅在首次发布时展示（编辑模式跳过）

### A4. 过期日期默认值优化
- 药品类默认有效期 = 今天 + 365 天（非处方药通常 1-2 年）
- 耗材类默认 = 今天 + 180 天
- 工具类默认 = 长期有效（`noExpiry` 自动勾选）

**预计文件变更**: `index.html` +15/-5, `app.js` +60/-15, `styles.css` +40/-10

## 迭代 B — 登录流程精简

**目标**: 登录卡片当前 5 个区域堆叠，视觉噪音大，改为分步渐进式。

### B1. 分步表单
```
Step 0: 同意协议 → 显示协议摘要 + "同意并继续"按钮
Step 1: 输入邮箱前缀 → "@smail.nju.edu.cn" 后缀
Step 2: 选择登录方式 → [验证码] [密码]
Step 3: 验证 / 输入密码 → 登录
```
- 已勾选协议且已登录过的用户可跳过 Step 0
- 当前已登录态直接跳过所有步骤

### B2. 折叠"南哪小帮手"
- 从 `<details>` 改为折叠面板，默认收起
- 仅显示一行"使用南哪小帮手登录 →"，点击展开

### B3. 忘记密码 / 设置密码分离
- "忘记密码？"链接点击后进入独立流程，不嵌套在登录卡片内
- "设置密码"提示改为登录成功后的小横幅，而非占位区域

### B4. 登录卡片视觉简化
- 减小内边距、合并间距
- 5 个区域 → 2 个可见区域（邮箱 + 登录方式），其余按需展开

**预计文件变更**: `index.html` +50/-80, `app.js` +80/-40, `styles.css` +30/-20

## 迭代 C — 空状态与过渡动画

**目标**: 空白页面不再只有文字，增加插画和动效提升完整体验。

### C1. 空状态插画
- 搜索无结果 → 放大镜 + 文件图标 SVG
- 我的发布为空 → 空盒子图标 + "发布第一件物品"按钮
- 网络错误 → 云朵断开图标 + 重试按钮
- **实现**: 纯 CSS/SVG 内联图标，不依赖外部资源

### C2. 页面切换过渡
- 三个主标签切换 → 淡入淡出 (200ms opacity crossfade)
- 详情弹窗 → 从底部滑入 (`translateY` + opacity)
- **实现**: CSS `@keyframes` + JS 切换 class

### C3. 弹窗进出动画
- `<dialog>` 打开 → `scale(0.95)→scale(1)` + `opacity 0→1`
- 关闭 → 反向动画，`close()` 延迟 200ms 执行
- **实现**: `dialog[open]` 动画 + `setTimeout` 延迟关闭

### C4. 加载骨架屏扩展
- 详情弹窗内联系方式加载 → 文字骨架
- 我的物品列表刷新 → 已有骨架屏，确认覆盖

**预计文件变更**: `index.html` +30/-10, `app.js` +15/-5, `styles.css` +80/-10

## 迭代 D — 响应式深度打磨

**目标**: 320px–480px 窄屏上的体验不妥协。

### D1. Chips 横向滚动
- `< 480px` 时 chips 区域改为 `overflow-x: auto` + 隐藏滚动条
- 左侧渐变遮罩提示可滚动
- "全部" chip sticky 固定在左侧

### D2. 表单按钮等宽 + 堆叠
- 发布表单提交按钮全宽
- `.auth-row` 按钮在 `< 460px` 时改为竖向堆叠（部分已有，全面检查）

### D3. 弹窗全屏模式
- `< 480px` 时 `dialog` 占满整个视口（`width: 100vw; height: 100dvh; border-radius: 0`）
- 关闭按钮改为左上角 sticky

### D4. 触摸目标放大
- 小型按钮 (`.small`) 最小触摸区域 ≥ 44px（已在 48px，检查一致性）
- chip 间距增大，减少误触

### D5. 详情弹窗移动端优化
- 物品图标缩小
- "查看联系方式"按钮 sticky 在底部

**预计文件变更**: `index.html` +5/-0, `styles.css` +60/-15

## 迭代 E — 微交互与反馈

**目标**: 操作反馈更细腻，状态变化更可感知。

### E1. 操作成功内联反馈
- 物品删除 → 卡片原地淡出 (300ms) + 高度收缩 → 下方卡片上移
- 领取确认 → 按钮变为 ✓ "已确认" 绿色态，1.5s 后卡片淡出

### E2. 物品过期倒计时
- 有效期 ≤ 7 天 → 卡片右下角橙色 `⏳ 还剩 X 天`
- 有效期 ≤ 3 天 → 红色
- 已过期 → 现有 `已过期` badge + 卡片整体降低透明度

### E3. Chips 选择反馈
- 点击 chip → 微缩放动画 `scale(0.92)` → 回弹
- 筛选结果数量变化时 `.item-list` 位移动画

### E4. Toast 改进
- 增加图标（✓ 成功 / ✗ 错误 / ℹ 信息）
- 增加手动关闭 × 按钮（当前仅点击任意位置关闭）
- 多个 toast 堆叠而非替换

### E5. 联系方式查看计数动画
- 剩余次数从 N→N-1 的数字翻转动画
- 次数用尽时按钮变为灰色 "今日次数已用完"

**预计文件变更**: `index.html` +10/-5, `app.js` +50/-20, `styles.css` +80/-15

## 依赖关系

```
A (表单) ──┐
B (登录) ──┤  无强依赖，可按优先级排列
C (空状态) ─┤
D (响应式) ─┤
E (微交互) ─┘
```

所有迭代彼此独立，可任意调整顺序。

## 推荐顺序

**A → E → C → D → B**

理由：表单是核心转化路径（A 优先），微交互提升整体感知质量（E），空状态和过渡让应用更完整（C），响应式是兜底体验（D），登录重构影响面大放最后（B）。
